**Proof of concept** – experimental build for enthusiasts; it installs kernel modules on your player. Use at your own risk.

New in 0.2.6:

- **No kernel panic after quick stop / start / seek actions.** At a playback start the composition re-registers its display buffers; when they changed, the `dvfel` module reallocated them while a frame slot was still reserved and marked every slot free, the reserved one too. The slot was then reserved twice, and one of its frames went to the video composer pointing to dvfel's own copy of a frame – the player rebooted (`videocomposer_vf_put`, in the vsync interrupt). dvfel now keeps its reserved slots, reallocates only while no other slot is in use, and records every frame it takes from the decoder side: each goes back exactly once, anything else is refused and logged instead of passed on.
- **No kernel panic in the H.265 decoder's back end.** The firmware's H.265 decoder declares its back end hung after 8–12 ms without progress (`decode_timeout_back_fast_check`); when the back end was only slow and its interrupt came anyway, `vh265_back_irq_cb` read a picture that was already gone and the kernel panicked. With two HEVC streams at once (4K base layer + enhancement layer) this check fires now and then, mostly at a playback start. VLC FEL's boot script now turns it off; the regular 200 ms back-end timeout still recovers a decoder that really hangs.
- **No flicker with single track files that partly lack the enhancement layer.** Some files muxed to a single track from a dual layer source whose enhancement layer had another picture order carry neither the EL nor the RPU in many access units. Those pictures went to the display as the plain base layer between fully composed ones (flicker), and the broken EL chain stalled the EL decoder every ~2 s. Now such a picture gets the last RPU again (it keeps the Dolby Vision mapping), and after an access unit without EL the EL decoder waits for its next key picture instead of decoding a broken chain. Proper FEL files never have such access units; nothing changes for them.

Kernel module `dvfel 2026.10.15.1` and libdvfelplay `2026.10.15.3` are new; VLC patches and `mvc3d` unchanged. The update replaces the installed module (VLC FEL asks for root access if it is off) and its boot script. Everything from 0.2.5 as before.

**Tested:** Dune HD Pro One 8K Plus (R24): `tools/tests/stopstart.sh` – 40 rounds of force-stop / BACK / restart with 1–3 seeks right after the start, with single and dual track P7 FEL test files: no panic, no refused frame, no lost slot (the reallocation path that crashed before ran 36 times); with the fast check off, 0 back-end fast-check timeouts in 40 rounds (10 with it on). A single track MP4 that lacks the EL and the RPU in 381 of 722 access units: 719 of 722 frames shown, 0 late, all with the Dolby Vision mapping, 0 as the plain base layer (before: 369), no EL decoder stall; a complete single track MKV: every frame composed with the EL, seeks as before.

### Install / update
Install `VLC-FEL-0.2.6-poc-armeabi-v7a.apk` over an older version (or new). Details, notes and uninstall: `README.txt` (Hungarian / English).
